# Feedback Letter conventions

Drawn from the first letters Instructors sent. This template is the reference: follow it, not an earlier gist.

`<course>`, `<prefix>` and `<signature>` are the values of the `feedbackLetter` block in `publisher.json`.

## Naming

- **File:** `<prefix>-<name>-<first-name>-feedback.md`, lower case, ASCII, hyphens, accents dropped: for a Student called DUPONT-LEROY Élodie Marie under the prefix `craft-2027`, `craft-2027-dupont-leroy-elodie-marie-feedback.md`.
- **Gist description:** `<course> — <NAME First-name> : <Competencies> — <angle in a few words>`:
  - `<course> — DUPONT Jeanne : C3 — why Solid`
  - `<course> — MARTIN Paul Louis : C1 & C2 — provisional Bands and catch-up`
  - `<course> — NGUYEN Linh : C1 & C2 — leads to reach Solid`

## Voice

A letter from `<signature>` to one Student, in English: direct, warm, second person. Short bullets, each opening with a **bold claim** followed by its evidence. Name each Competency with its id and its title from the grid the first time it appears, for example `C2 (<title as the grid writes it>)`. Write the Band names exactly as the grid does.

## Verdict letter

```
Hi <First-name>,

<One paragraph: the Band per Competency, in bold. If the Student missed the Oral, the Bands are provisional, and the Oral is where the work is verified.>

## <Cx> — <Band>                       (a heading per Competency when there are several)

**What works, and I had an agent check it against your work:**
- <bold claim.> <evidence: file, issue, commit, passage, command output>

**Why not <next Band>:**
- <the missing criterion, in the grid's own terms>

<Optional: a catch-up section, only when the Instructor offers one, with the Oral questions and one or two follow-ups taken from the weakest points.>
<Optional: a risk to fix, such as a committed secret, and how to fix it.>

Good work on <what was strongest>!

<signature>

PS: this message was generated by an agent under my control.
```

When a document in the Student's work reads as largely agent-written, say so in the _Why not_ list, in these words: "Using an agent is not a reproach, since working with agents is part of what is assessed. What is assessed is your ability to defend what the agent produced, and only the Oral shows that."

## Hints letter

For a Student close to the next Band. It gives leads, never the answers.

- A title: `# Step 1 — <from where to where>`.
- A context block: the evidence read, the grid reference (the Competencies and the target column), the Instructor's Oral remarks quoted as given, and what the re-read found, with the date it was read.
- A section per Competency: the grid's target criterion quoted, what the work shows today, then **numbered leads** phrased as questions or tests the Student runs themselves, and the Oral question that will check it.
- `## Reminders`: justification counts for more than artifacts.
- `## Skills worth trying in your next session`: the agent skills that fit the leads, when the course teaches any.
- `## Stuck or unclear?`: asking for clarification is welcome and never counts against you.
- The sign-off and PS, as in the verdict letter.

### The hidden step 2 (two revisions)

When the Instructor wants the answers to be findable by a Student who pays attention:

1. Create the gist with two files: the letter, and `2-what-was-left-out-on-purpose.md`, which holds the answers.
2. Edit it: delete the step 2 file (`gh gist edit <id> --remove <file>`), and add a note below the title saying that step 2 can be reached from this gist by a Student who pays attention to details, either through its first revision or by digging into the work it concerns. The answers now live only in revision 1.
3. Check with `gh api gists/<id>/commits --jq length` that there are two revisions, and with `gh gist view <id> --files` that only the letter remains.

A later revision after the Oral is a third revision on the same gist: read the gist first, as `SKILL.md` step 4 says, and never restore the step 2 file.
